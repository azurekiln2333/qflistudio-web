`libqfli_web_cdp_transport.so` as
`file:./src/main/cpp/types/libqfli_web_cdp_transport`. The local package exists,

The CDP package is absent from all three current resolution surfaces:
`entry/oh-package-lock.json5`, the entry dependency map inside
`ohos/oh_modules/.ohpm/lock.json5`, and `entry/oh_modules`. This is an actual
unresolved local dependency, not an observed ArkTS compiler error. Refresh it
through OHPM before the full application type/import gate; do not hand-edit
the autogenerated locks or create a replacement manual junction.

All six existing entry-lock package paths resolve to retained local files or
directories: Flutter embedding, arm64/x64 native HARs, integration_test,
path_provider_ohos and Nginx types. Root Hypium1.0.6 is also installed locally,
but the root lock records its external registry URL.

Installed OHPM26.0.0.630 source registers the hidden `--module` and

1. **OHOS native-only window:** request one named window of up to180s, with
   suspended-start private Job containment before execution, at most150s work,
   cleanup through170s and terminal/empty-Job publication through180s. These
   are planning limits, not measured durations. Recheck/fingerprint inputs,
   build only the target with one compiler job, one ABI at a time, then inspect
   each produced ELF and record its full SHA256. Stop on the first failure;
   mark the other ABI unrun. Do not start a new phase after140s.
2. **Linux fixture window:** obtain a separate named Linux/WSL grant; compile
   the exact connector with `bash scripts/test_web_cdp_transport.sh <fresh-output>`.
   The script's runtime fixture is bounded to30s, but the outer owned job must
   also bound compilation and cleanup. Record all seven actual cases, exit
   codes and source/library hashes. This excludes NAPI and OHOS execution.
3. **Resolution and application window:** separately contain the module-only
   OHPM refresh, then the real Hvigor API26 ArkTS/ArkUI/test-target build and
   archive inspection. Preserve unrelated startup WIP, existing normal HAPs
   and locks before tool changes. Full app compilation is the import/type gate;
   the earlier TypeScript protocol fixture cannot replace it.
4. **Own-app device window:** only after current target identity/ABI and device
   ownership are reconciled, cold-start the opt-in Unix-only test ability and
   collect current HAP/core/OS/API/ArkWeb/PID identity. Require exact random
   target/frame binding, actual Runtime42 response and owned cleanup. Inbound
   authorization, target/socket disappearance, stop/relaunch and actual Debugger
   control remain separate assertions; compilation cannot close R8/R10.

The exact native-only commands, to run inside the first owned window, are:

```powershell
$cdpSdkNative = 'D:/ProgramFiles/Huawei/DevEco Studio/sdk/default/openharmony/native'
$cdpCmake = "$cdpSdkNative/build-tools/cmake/bin/cmake.exe"
foreach ($cdpAbi in @('arm64-v8a', 'x86_64')) {
  & $cdpCmake --build "ohos/entry/.cxx/default/default/release/$cdpAbi" --target qfli_web_cdp_transport --parallel 1
  if ($LASTEXITCODE -ne 0) { throw "Native target failed for $cdpAbi" }
  $cdpLibrary = "ohos/entry/build/default/intermediates/cmake/default/obj/$cdpAbi/libqfli_web_cdp_transport.so"
  & "$cdpSdkNative/llvm/bin/llvm-readelf.exe" --file-header --program-headers --dyn-syms --dynamic $cdpLibrary
  if ($LASTEXITCODE -ne 0) { throw "ELF inspection failed for $cdpAbi" }
}
```

Require DYN/zero entry, the correct AArch64/x86-64 machine, LOAD alignment at
least0x4000, all four default-visible `qfli_web_cdp_*` exports, and recorded
NAPI/pthread/libc++ dynamic dependencies/imports. Capture diagnostics rather
than interpreting a file's existence as success. NAPI registration, argument
boundaries, per-environment cleanup and actual module import remain unrun.
